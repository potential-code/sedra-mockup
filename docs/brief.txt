Build this experience
Create a bilingual SEDRA learning mockup for people of determination aged 13–35. Make learning as easy to navigate as a short-video app: one clear task at a time, a prominent next step and reliable replay. Every learner must be able to use buttons instead of gestures and text instead of audio. Accessibility must shape the lessons, interactions and navigation throughout.
Aliya owns the platform build and content entry. Vera owns production of the two selected 30-second sample videos, captions and transcripts, then hands those assets to Aliya. All 16 units below have complete English scripts and checks. Only LS02 and HF01 require actual video production for this mockup; the remaining videos are pending production and must be labelled accurately.

Core journeys
New learner: Home → Welcome → Preferences → Dashboard → Programme → Unit → Check → optional practice → Next. Returning learner: Continue learning restores the same unit and step, with media paused. Programme switching never resets progress. Help returns to the original place.
Recorded session: Dashboard → Sessions → Recordings → choose a recording → captions/transcript/resources. Viewing a recording is separate from course completion. No missed-session penalty.
Supporter assistance: allow a learner to request help and demonstrate a supporter alongside them; do not create a guardian dashboard that exposes records automatically. Before production, SEDRA must approve consent and access rules, including its process for minors.
3 Navigation and accessibility
One task per screen
Mobile: single-column card, player above a sticky action area. Bottom navigation contains Home, Learn, Sessions and Help, each with icon and text. Keep the unit sequence visible as Unit 2 of 8. Desktop uses the same sequence with a compact course outline. Simplified view hides optional resource cards and secondary statistics; essential controls and help remain.
A swipe may navigate between unit overview cards only. Always provide Previous unit and Next unit buttons; never require a swipe, drag, long press, double tap, fast response or precise pointer movement. Checks remain in place until the learner selects an action. Moving away from unfinished work prompts Keep learning or Leave and save. All media pauses when a unit loses focus.
Area
Build requirement and acceptance check
Touch and layout
Use at least 48 by 48 CSS pixel primary controls and 8-pixel spacing. At 320 CSS pixels wide, no horizontal page scrolling. Verify 200% text zoom and 400% browser zoom without hidden actions.
Reading
Default learner body text 18 px, generous line spacing and left alignment in English/right in Arabic. Text controls 100%, 125%, 150%. Use brief sentences, everyday words and labelled illustrations. Never justify learner text.
Contrast
Use #4b662f on white for headings and white on #4b662f for primary actions. Measure every final pair. Target at least 4.5:1 normal text, 3:1 large text and essential controls; pale green is a panel colour, not small text on white. Offer black/white high contrast.
Keyboard
Everything works using Tab, Shift Tab, Enter, Space and arrows where appropriate. Skip to main content first. Visible focus ring; logical sequence; no keyboard traps. Focus returns to the opener after a dialog closes.
Screen reader
Semantic headings, landmarks and labelled form controls. Announce progress and feedback politely without reading the whole screen repeatedly. Radio groups have question legends; disabled controls explain why. Label each player and icon.
Media
No autoplay. Captions on by default; transcript and image descriptions adjacent. Pause, replay, volume, speed and full-screen controls reachable by keyboard. Avoid flashing, loud surprises and distracting music. Essential visual actions also appear in narration or descriptive transcript.
Checks
Untimed, unlimited attempts, no negative points. Wrong answers retain the screen and show a useful hint. Never use colour alone for correctness. Provide button choices for sorting and matching; optional typing only.
Preferences
Persist language, text size, contrast, captions and reduced-motion preferences. Respect system reduced motion. Read-aloud is optional and user-initiated, with stop controls; it must not conflict with screen-reader speech.
Emotional safety
Recognise that feelings vary. Do not force smiling, eye contact, touch, breathing exercises or personal disclosures. Accept spoken words, gestures and communication aids. A learner can choose a comfortable way to participate.
Errors
Plain language beside the field plus an error summary; preserve entered text. Example: Choose one answer, then select Check answer. No silent failure or vanishing message.
These are implementation acceptance targets. The mockup must not display a certified accessibility or compliance claim. Test with SEDRA participants with varied communication, sensory, motor and cognitive access needs; do not assume one configuration fits everyone.

Course behaviour used by every unit
Each unit contains a 30-second video, the summary below, one untimed check and an optional practice action. The 30 seconds describes media duration, not time allowed for the whole unit. Transcript or storyboard access is an equal learning route. Expose Next after the answer has been reviewed, including after an incorrect answer; allow learner choice to retry or continue with support. Record check outcome separately from completion. Completion requires Watch or read done plus Check reviewed; optional practice can be Done / Later / With help and does not block progress. Allow replay and revisiting all units. No watch-percentage gate or expired access.
For pending videos show Video being prepared with the complete storyboard and Read lesson action. Do not show a broken player, pretend placeholder content is a produced video, or substitute the external YouTube video for all units. Eight units per course give four minutes of planned video, plus checks and practice at the learner’s own pace.
